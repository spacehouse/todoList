# H2 存储迁移 M2 详细计划：TCP 外部访问

## 关联总计划

- 总计划：[h2-storage-migration-plan.md](h2-storage-migration-plan.md)
- 本阶段增加 H2 TCP Server、三级账号和运维状态命令。

## 通用执行门禁

- 每个阶段开始前先确认上一个阶段的验收项已通过；未通过时不得继续叠加下一阶段功能。
- 每个阶段只实现本阶段明确列出的能力；发现需要跨阶段能力时，先更新总计划和本阶段文档并说明原因，再实施。
- 每个阶段都必须保持 `storageBackend=nbt` 可用，且 NBT 模式不得加载、初始化或写入 H2。
- 每个阶段都必须保持现有命令、GUI、HUD、网络同步行为不因未开启 H2 而变化。
- 每个阶段的 Java 新增类和新增方法都必须按项目规则补充简短说明注释。
- 每个阶段完成后执行对应阶段测试；涉及代码实现阶段还要执行 `.\build-with-java21.bat --offline build`。
- 发现中文乱码、旧 `.dat` 被意外修改、H2-only 数据被旧 NBT 覆盖、或 H2 失败后内存出现未保存脏状态时，立即停止本阶段并先修复问题。

## 阶段内审查循环

- 实施前按“执行前检查清单”和“禁止事项”审查。
- 每完成一个实施步骤，按“验收标准”和“最小测试矩阵”复审。
- 发现计划缺口时，先改进总计划和本阶段文档，再继续实施。
- 重复审查和改进，直到没有新的计划改进建议。

## 目标

- 在 M1 嵌入式 H2 可用的基础上，提供可选 H2 TCP Server 和受限外部 SQL 账号。
- TCP 开启时统一内部 DAO 连接模式，避免嵌入式连接与 TCP 外部连接混用。

## 阶段输入

- M1 已稳定的 H2 嵌入式连接、DAO、状态模型和不可用状态。
- 目标 H2 版本已验证可用的 TCP Server API 与权限语法。
- 当前命令权限判断方式和服务端/客户端日志输出方式。
- 当前 H2 数据库路径派生规则和 namespace 生命周期。

## 执行前检查清单

- 确认 M1 的嵌入式 H2、迁移、fallback 和不可用状态测试已通过。
- 确认目标 H2 版本的 TCP Server API 和权限 DDL 已在 M1-0 或补充 spike 中验证。
- 确认 TCP 默认关闭，不影响 M1 嵌入式行为。
- 确认命令权限模型能区分控制台、OP 和普通玩家。

## 阶段产出

- `config/todolist-h2.json` 配置模型、安全默认值和损坏配置恢复逻辑。
- TCP Server 生命周期管理、端口递增和状态快照。
- admin、readonly、readwrite 账号初始化、密码重置和权限自愈。
- `/todolist h2 status`、`restart-tcp`、`reset-password <role>` 命令。
- TCP/嵌入式切换、失败回退、权限和脱敏测试。

## 实施步骤

1. 新增 `config/todolist-h2.json` 配置读写组件，支持损坏配置 `.corrupted` 保留和安全默认重建。
2. 定义 TCP 开关、绑定地址、端口、自动递增端口、远程访问、数据库路径覆盖和账号凭据字段。
3. 实现密码生成、重置和脱敏日志；远程访问开启时拒绝默认弱密码。
4. 实现 `H2TcpServerManager`，负责启动、停止、重启、端口递增和状态快照。
5. TCP 启动成功后切换 DAO URL 为 TCP URL；未启用或启动失败时回退嵌入式 file URL。
6. 实现 admin、readonly、readwrite 账号初始化和权限自愈；重复启动可修正被手动改坏的权限。
7. 新增 `/todolist h2 status`、`restart-tcp`、`reset-password <role>` 命令和权限判断。
8. 完善错误状态：TCP 失败但嵌入式可用、嵌入式也锁定、H2 不可用但旧 `.dat` 只读 fallback、完全不可用。
9. 补充 Windows 绝对路径、空格、中文路径下 TCP URL 的连接测试。

## 禁止事项

- 不改变 M1 默认嵌入式行为；TCP 默认关闭。
- 不把密码或完整 JDBC URL 写入日志、聊天提示或状态命令。
- 不允许 readonly/readwrite 执行 DDL。
- 不在 TCP 启动失败时清空内存或误判为无数据。
- 不实现备份、维护锁扩展或 GUI/HUD SQL 查询优化。
- 不允许 TCP 模式和嵌入式模式同时对同一数据库保持活动连接。

## 停止条件

- TCP URL 无法稳定支持 Windows 盘符、空格或中文路径。
- TCP 启动成功后内部 DAO 仍会继续使用嵌入式 URL。
- 密码、完整 JDBC URL 或 admin 凭据会进入日志、聊天或异常文本。
- readonly/readwrite 权限无法通过重复启动自愈。
- TCP 失败路径会清空内存或覆盖 M1 的不可用状态。

## 验收标准

- TCP 默认关闭时，M1 嵌入式行为不变。
- TCP 开启成功时，内部 DAO 和外部客户端均通过 TCP 访问同一数据库。
- 端口冲突时自动递增，实际端口能在日志和状态命令中看到。
- readonly 只能 SELECT；readwrite 能 DML 但不能 CREATE/ALTER/DROP；admin 仅内部使用。
- 配置损坏时保留 `.corrupted`，生成安全默认配置和新随机密码。
- TCP 启动失败时回退嵌入式；嵌入式也失败时进入存储不可用状态并清晰提示。
- `.\build-with-java21.bat --offline build` 和 M1 回归测试仍通过。

## 可进入下一阶段条件

- TCP 生命周期、账号权限、状态命令、故障回退和安全脱敏测试全部通过。
- 确认外部 SQL 访问不会绕过 M1 的 schema 和迁移安全边界。

## 最小测试矩阵

- 配置：缺失配置、合法配置、损坏配置、远程访问弱密码、密码重置。
- 端口：默认端口可用、默认端口冲突、自动递增耗尽或失败。
- 路径：Windows 盘符、空格路径、中文路径、数据库路径覆盖。
- 连接模式：TCP 成功时内部 DAO 使用 TCP URL；TCP 关闭/失败时使用嵌入式 URL。
- 权限：readonly SELECT 成功但 DML/DDL 失败；readwrite DML 成功但 DDL 失败；admin 不暴露给外部提示。
- 状态命令：正常、TCP 回退嵌入式、嵌入式锁定、fallback、完全不可用。
- 安全脱敏：日志、命令输出、异常提示中不包含密码或完整 JDBC URL。

## 回滚方式

- 将 TCP 配置开关关闭，内部 DAO 回到 M1 嵌入式 file URL。
- 若 TCP 配置损坏，保留 `.corrupted` 并生成安全默认配置。
- 不删除 H2 数据库文件，不重置 M1 迁移状态。

## 文档同步要求

- TCP 配置字段、默认端口、账号权限或状态命令输出发生变化时，同步更新总计划 M2 小节。
- 连接模式回退语义发生变化时，同步更新 M1 fallback 说明和 M3 运维组合测试。
