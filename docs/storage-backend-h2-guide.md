# 底层数据模式切换与 H2 模式使用说明

## 这份文档解决什么问题

如果你准备在 `NBT` 文件存储和 `H2` 数据库存储之间切换，或者已经启用了 `H2` 但还不清楚：

- 应该改哪个配置文件
- 首次切换时会不会自动迁移旧数据
- `H2 TCP` 什么时候会启动
- 外部工具怎么接入
- 遇到端口冲突、配置损坏、存储不可用时该看哪里

这份文档就是给这些场景准备的。

---

## 一、先看结论

当前版本支持两种底层数据模式：

| 模式 | 配置值 | 适用场景 | 特点 |
|---|---|---|---|
| NBT 文件存储 | `nbt` | 轻量单人、简单本地使用 | 默认模式，结构直观，不依赖数据库 |
| H2 数据库存储 | `h2` | 数据量更大、需要更稳的写入恢复、需要备份、需要外部 SQL 工具 | 支持关系型查询、在线备份、TCP 外部访问 |

最重要的边界只有两条：

1. `NBT` 和 `H2` 不是双写模式。
2. 从 `H2` 临时切回 `NBT` 只是应急回退，不会把 `NBT` 期间新增的数据自动同步回 `H2`。

---

## 二、相关文件和目录

### 1. 主配置文件

路径：

```text
config/todolist.json
```

这里控制当前使用哪种底层存储模式：

- `storageBackend`
- `h2BackupOnStart`

### 2. H2 TCP 配置文件

路径：

```text
config/todolist-h2.json
```

这个文件只在 H2 场景下有意义，用来控制：

- 是否启用 TCP
- 绑定地址和端口
- 是否允许远程连接
- 数据库路径覆盖
- 外部账号和密码

### 3. 数据目录

默认数据都在：

```text
todo/<namespace>/
```

其中 `<namespace>` 是当前存储域。常见理解方式：

- 单人本地世界通常是 `local`
- 多人/联机环境会派生出对应的命名空间目录

在 H2 模式下，默认数据库主文件基础路径是：

```text
todo/<namespace>/todolist
```

实际 H2 文件通常会表现为：

```text
todo/<namespace>/todolist.mv.db
```

旧版 NBT 数据文件仍会保留在同一套 `todo/<namespace>/` 目录结构下，不会因为切到 H2 就自动删除。

## 三、如何切换底层数据模式

### 3.1 从 NBT 切到 H2

### 适合什么时候切

建议在以下场景切到 `H2`：

- 任务、项目、玩家状态数据已经比较多
- 你希望保存更稳定，减少整文件反复重写
- 你需要做在线备份
- 你希望通过外部工具读取数据库
- 你准备在局域网开放或服务器环境下长期使用

### 操作步骤

1. 完全关闭游戏或服务器。
2. 打开 `config/todolist.json`。
3. 将 `storageBackend` 改为 `h2`。
4. 可选地把 `h2BackupOnStart` 改为 `true`，这样每次 H2 初始化完成后会额外做一次启动备份。
5. 保存配置并重新启动游戏或服务器。

推荐配置示例：

```json
{
  "storageBackend": "h2",
  "h2BackupOnStart": false
}
```

### 首次启动后会发生什么

首次以 `H2` 模式启动时，程序会按当前命名空间执行以下动作：

1. 创建或打开 `todo/<namespace>/todolist.mv.db`
2. 初始化 H2 schema
3. 检查旧 NBT 数据是否已经迁移
4. 如果还没迁移过，就把旧 `.dat` 数据导入 H2
5. 迁移完成后，后续读写都走 H2

这里有几个关键点：

- 旧 `.dat` 文件不会自动删除
- 迁移完成后，不会在每次启动时重复导入旧 `.dat`
- 如果 H2 已经存在迁移后的数据，再切回 `H2` 时不会拿旧 `.dat` 覆盖它

### 如何确认切换成功

如果你有管理员权限，可以在游戏内执行：

```text
/todo h2 status
```

重点看这几项：

- `H2 存储后端：h2`
- `H2 可用性：available`
- `H2 当前连接模式：embedded` 或 `tcp`

如果这里仍显示后端不是 `h2`，说明主配置没有生效。

---

### 3.2 从 H2 切回 NBT

### 什么时候应该切回

只建议在这些场景切回 `NBT`：

- 你要做紧急回退
- 当前 H2 配置损坏，需要先恢复基本可用性
- 你明确决定不再使用 H2

### 操作步骤

1. 完全关闭游戏或服务器。
2. 打开 `config/todolist.json`。
3. 将 `storageBackend` 改回 `nbt`。
4. 保存后重新启动。

示例：

```json
{
  "storageBackend": "nbt",
  "h2BackupOnStart": false
}
```

### 必须注意的风险

切回 `NBT` 后：

- 程序会强制使用旧 NBT 文件
- 不会再从 H2 中读取数据
- 也不会把 NBT 新增的数据自动回灌到 H2

这意味着：

如果你在 `NBT` 模式下继续使用了一段时间，再把 `storageBackend` 改回 `h2`，H2 不会自动吸收这段时间在 NBT 中新增的内容。

所以，`H2 -> NBT -> H2` 这条路径一定要理解成：

```text
应急回退，不是双向同步
```

## 四、H2 模式的三种运行状态

当 `storageBackend=h2` 时，实际运行中有三种状态：

### 1. embedded

最常见，也最稳。

含义：

- 使用本地嵌入式 H2 连接
- 不对外暴露 TCP 端口
- 适合单人、本机使用、无需外部 SQL 客户端接入的场景

### 2. tcp

表示 H2 TCP Server 已成功启动。

含义：

- 模组内部和外部客户端都通过 TCP 方式访问数据库
- 适合局域网、服务器、外部管理工具接入

### 3. embedded_fallback

表示你配置了 TCP，但 TCP 启动失败，程序回退到了嵌入式模式。

常见原因：

- 端口被占用
- 绑定地址不合法
- 远程访问配置不满足安全要求
- H2 TCP 启动过程报错

这种状态下：

- 模组本体仍尽量保持可用
- 外部客户端无法通过 TCP 连接
- 你应该尽快执行 `/todo h2 status` 和查看日志确认原因

## 五、H2 TCP 模式怎么开

### 5.1 默认行为

首次生成的 `config/todolist-h2.json` 是安全默认值：

- `tcpEnabled=false`
- `port=9092`

TCP 服务器固定只接受**本机回环（127.0.0.1）**连接，用作同进程内部通道，**不提供任何远程访问能力**。历史配置里的 `bindAddress`、`allowRemote` 字段会被直接忽略。

### 5.2 本机 TCP 访问

如果你只是想让本机 SQL 工具连接，推荐这样配：

```json
{
  "tcpEnabled": true,
  "port": 9092,
  "autoIncrementPort": true,
  "maxPortAttempts": 16,
  "databasePathOverride": ""
}
```

说明：

- TCP 服务器始终只允许本机回环连接，远程机器无论怎么配置都连不上
- 如果 `9092` 被占用，且 `autoIncrementPort=true`，会自动尝试后续端口

启动后可执行：

```text
/todo h2 status
```

查看最终实际端口。

### 5.3 从其他机器访问数据库（SSH 隧道）

TCP 服务器不开放远程访问。如果你部署在云主机上，想从自己电脑用 DBeaver/DataGrip 等工具查库，标准做法是走 SSH 隧道：

```text
ssh -L 9092:127.0.0.1:9092 user@云主机IP
```

然后在数据库工具里连接 `127.0.0.1:9092`，效果与本机直连完全一致，且流量全程走 SSH 加密，数据库对外零暴露。

## 六、H2 TCP 账号体系怎么用

当前有三类账号：

| 角色 | 用途 | 权限建议 |
|---|---|---|
| `admin` | 模组内部主要使用 | 不建议外部长期使用 |
| `readonly` | 外部只读查询 | 适合报表、排查、只读工具 |
| `readwrite` | 外部读写 | 适合明确知道自己在做什么的维护场景 |

默认用户名分别是：

- `todo_admin`
- `todo_readonly`
- `todo_readwrite`

建议这样理解：

- 日常查看数据，只用 `readonly`
- 需要外部写入时再考虑 `readwrite`
- `admin` 主要给模组自身保留，不要当成日常外部账号

如果需要重置密码，可以执行：

```text
/todo h2 reset-password admin
/todo h2 reset-password readonly
/todo h2 reset-password readwrite
```

执行后需要到 `config/todolist-h2.json` 中读取新的密码，并同步更新外部客户端连接配置。

注意：

- 命令反馈不会直接把密码打印到聊天栏里
- 配置文件损坏时，系统会保留原文件为 `.corrupted`，然后生成新的安全默认配置

## 七、常用 H2 运维命令

### 1. 查看状态

```text
/todo h2 status
```

适合确认：

- 当前后端是不是 `h2`
- H2 当前是否可用
- 运行在 `embedded`、`tcp` 还是 `embedded_fallback`
- TCP 实际绑定地址和端口
- 最近一次失败原因

### 2. 重启 TCP

```text
/todo h2 restart-tcp
```

适合场景：

- 改了 `todolist-h2.json`
- 端口占用环境发生变化
- 你想重新尝试 TCP 绑定

### 3. 在线备份

```text
/todo h2 backup
/todo h2 backup <name>
```

适合在改配置、做升级、做外部维护前先留一个备份。

### 4. 重载数据库上下文

```text
/todo h2 reload-db
/todo reload-db
```

适合在数据库维护后刷新当前内存上下文。

### 5. 健康检查

```text
/todo h2 health
```

会输出：

- 当前 schema 版本
- 任务数量
- 健康检查是否通过

## 八、推荐使用方式

### 8.1 纯单人、本地轻量使用

建议：

```text
storageBackend=nbt
```

理由：

- 配置最简单
- 不需要额外理解数据库
- 适合轻量使用

### 8.2 单人但数据较多，或者经常改任务/项目

建议：

```text
storageBackend=h2
tcpEnabled=false
```

理由：

- 享受 H2 的写入稳定性和备份能力
- 仍保持嵌入式模式，风险更低

### 8.3 局域网、私人服务器、希望接 SQL 工具

建议：

```text
storageBackend=h2
tcpEnabled=true
```

本机接 DBeaver、DataGrip 之类工具直接连 `127.0.0.1` 即可。

如果要从其他机器查库，用 SSH 隧道（见 5.3），不要尝试开放远程访问——当前实现从机制上不提供该能力。

## 九、切换和使用 H2 时的注意事项

### 1. 不要把它当成双写系统

再次强调：

- `NBT` 和 `H2` 之间没有自动双向同步
- 切换模式前最好先明确当前哪一份才是主数据

### 2. 切换前最好完全退出游戏或停服

虽然很多配置改完后重启就能生效，但底层存储切换本质上是持久化路径切换，最佳实践仍然是：

```text
先停，再改，再启
```

### 3. 第一次启用 H2 时不要手动删旧 `.dat`

原因很简单：

- 首次迁移要读旧数据
- 出现异常时，旧数据仍然是最重要的回退依据

### 4. 看到 `.corrupted` 文件不要慌

这通常说明：

- 配置文件损坏
- 程序已经帮你把坏文件保留下来
- 并重新生成了一份新的安全默认配置

这不是“自动删配置”，而是“先保留原件，再恢复可启动状态”。

### 5. 账号密码由程序自动管理

- 三组账号密码由程序自动生成高强度随机值（首次生成后固定写在 `todolist-h2.json`）
- 需要重置时执行 `/todo h2 reset-password`
- 不要把 `admin` 账号交给别人长期使用，日常排查优先用 `readonly` 账号

## 十、常见问题排查

### Q1：我改成了 `h2`，但还是感觉像在走旧文件？

先检查三件事：

1. `config/todolist.json` 里是不是确实保存成了 `"storageBackend": "h2"`
2. 有没有完全重启游戏或服务器
3. 执行 `/todo h2 status` 后，返回的后端是不是 `h2`

### Q2：我开了 TCP，但状态仍然是 `embedded_fallback`

优先排查：

1. 端口是否被占用
2. 日志里是否有 TCP 启动失败信息
3. H2 是否被系统安全软件拦截

### Q3：为什么切回 NBT 后，后来再切回 H2，看不到我在 NBT 期间新加的数据？

因为当前设计就是这样：

- H2 完成迁移后，不会把后续 NBT 改动自动再导入一次
- 这是为了避免混用两个后端后产生覆盖和误判

### Q4：局域网开放、退出世界、再回未发布单人，会不会把 H2 搞坏？

当前版本已经专门修复了这条生命周期链路里的旧连接复用问题。现在在：

```text
未发布单人 -> 对局域网开放 -> 退出 -> 再进入未发布单人
```

这条路径上，程序会主动失效旧上下文里的可复用连接，避免把已经关闭的旧 session 继续拿来写入。

如果你仍遇到“存储当前不可用”，优先查看日志和 `/todo h2 status` 的最近失败信息。

## 十一、建议的最稳操作流程

如果你是第一次切 H2，推荐按这个流程来：

1. 退出游戏或停服
2. 备份整个 `todo/` 目录和 `config/todolist.json`
3. 把 `storageBackend` 改为 `h2`
4. 启动一次，让程序自动建库和迁移
5. 进入游戏后执行 `/todo h2 status`
6. 确认 `H2 可用性` 为 `available`
7. 如果还要接外部工具，再单独配置 `todolist-h2.json`
8. 准备做结构调整或运维时，先执行一次 `/todo h2 backup`

这样切换最稳，出问题也最好回退。

---

## 十二、给不同用户的简版建议

### 玩家

如果你只是自己玩：

- 想省心，用 `NBT`
- 想更稳，用 `H2 + 嵌入式`

### 局域网房主

推荐：

- `storageBackend=h2`
- 平时 `tcpEnabled=false` 或只开本机 TCP
- 改配置前先备份

### 服务器服主或维护者

推荐：

- 使用 `H2`
- 明确区分 `readonly` 和 `readwrite`
- 远程访问前先确认密码强度、绑定地址和防火墙
- 用 `/todo h2 status`、`/todo h2 health`、`/todo h2 backup` 做日常维护
