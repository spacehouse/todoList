# TodoList GUI 重构示意图与开发计划

## 1. 目标
本轮不做 Microsoft To Do 的像素级复刻，而是对齐它在信息组织上的核心优点：安静、聚焦、连续、低负担。

本次改版重点解决以下问题：
- 明确区分“个人空间”和“团队空间”
- 让主界面中的保存、取消、配置、筛选、详情抽屉职责更稳定
- 让任务优先级表达回归已有产品认知，不再临时改成 `P1 / P2` 文本
- 统一主界面、弹窗、配置页、HUD 的视觉语言
- 为后续 GUI 重构与测试提供稳定基线

## 2. 设计定位

### 2.1 体验关键词
- 轻盈：弱化厚重描边和过多功能噪音
- 聚焦：中间任务区始终是主角
- 连续：新增、勾选、切换、查看详情保持一条操作流
- 熟悉：参考 Microsoft To Do 的阅读节奏
- 一致：主界面、弹窗和 HUD 属于同一套产品语言

### 2.2 视觉语气
- 外层仍保持浮于游戏画面上的悬浮工作台感受
- 左侧导航、中间主区、右侧抽屉形成三层亮度层级
- 重点色只用于选中态、主按钮和优先级提示
- 字号分层明确：标题、分组、正文、辅助信息四级
- HUD 与主界面保持一致的色彩语义，但保留更高透明度和更紧凑密度

## 3. 核心结构决策

### 3.1 空间切换
主界面左侧标题下方保留空间切换器：
- `个人空间 | 团队空间`
- 切换空间后，视图区立即切换
- 个人空间只显示 `我的`
- 团队空间只显示 `待分配 / 全部 / 我的`

### 3.2 主界面三段式结构
- 左侧导航区：空间、视图、项目
- 中间主任务区：标题、搜索、筛选、任务列表、快速新增
- 右侧详情抽屉：任务上下文编辑

### 3.3 固定区规则
- 左侧项目操作按钮固定在侧栏底部
- 中间快速新增输入框固定在主内容底部
- 主界面右上角固定显示 `保存`、`取消`、`配置`

### 3.4 滚动区规则
以下区域在内容超出可视范围时必须出现竖向滚动条：
- 左侧项目列表
- 主界面任务列表
- 右侧详情抽屉内容区
- Project Settings 中的成员列表
- 指派他人中的成员列表
- 添加成员中的成员列表
- 配置页中的配置列表

滚动条要求：
- 使用细窄竖向滚动条
- 轨道弱化，滑块可见但不过度抢眼
- 固定区与滚动区要明显分层，避免滚动时把底部按钮或顶部操作一起卷走

## 4. 主界面详细规则

### 4.1 左侧导航区
结构：
- 顶部：应用名
- 顶部下方：空间切换器
- 中部：视图列表
- 中下部：项目搜索与项目列表
- 底部固定区：`新建项目`、`编辑`、`删除`

规则：
- 三个项目按钮必须是明确的按钮样式，不能做成普通文字
- `新建项目`为主强调按钮
- `删除`使用风险色
- 项目列表滚动时，底部按钮区位置不变

### 4.2 中间主任务区
结构：
- 顶部左侧：当前列表标题 + 状态摘要
- 顶部右侧：`保存`、`取消`、`配置`
- 搜索筛选区：搜索框 + 单个下拉筛选按钮
- 列表区：未完成在上，已完成折叠在下
- 底部固定输入区：带 `+` 图标的快速新增输入框

规则：
- 当前只保留一个筛选入口：`按优先级 v`
- 筛选入口要做成可扩展下拉入口，为后续新增更多条件预留空间
- 快速新增框始终固定在底部
- 任务列表本身属于滚动区，列表超高时显示竖向滚动条

### 4.3 任务条目
任务条目优先级表达恢复为项目既有风格，不再使用 `P1 / P2 / P3` 文本。

每条任务包含：
- 优先级色块
- 勾选框
- 任务标题
- 辅助信息：标签、项目、分配对象等

优先级色块规则：
- 高优先级：红色
- 中优先级：黄色
- 低优先级：绿色
- 色块放在勾选框前方
- 已完成任务仍保留优先级色块，但整体对比度降低

表现规则：
- 当前选中项使用更明显底色
- 已完成项降低文字对比度
- 长标题在列表中可截断，在详情中完整展示

### 4.4 右侧详情抽屉
结构：
- 第一行：独立的关闭按钮行
- 第二行：任务标题区域
- 第三行开始：状态、项目信息、描述、标签、操作按钮

规则：
- 关闭按钮独占一行，不与标题同行
- 标题是可点击选中并进入编辑状态的，这一点必须在文档和实现中保留
- 保存按钮从抽屉中移除，统一放在主界面右上角
- 标签作为独立可编辑项，单独成一行或一个独立卡片
- 团队空间中的 `领取任务`、`放弃任务`、`指派他人` 使用一行一个纵向按钮，避免小尺寸下被挤出
- 个人空间中不显示这三个团队操作按钮
- 详情抽屉内容区属于滚动区，标题与关闭按钮不随描述、标签、按钮区一起滚动

### 4.5 已完成分组
规则：
- 默认收起：`> 已完成 N 项`
- 展开后：`v 已完成 N 项`
- 已完成项与未完成项共享同一任务条目结构，仍保留优先级色块

## 7. HUD 设计

### 7.1 HUD 目标
HUD 需要延续当前产品习惯，但提升阅读性与层级清晰度，不应完全改成主界面的小卡片复制品。

### 7.2 HUD 结构
- 标题行：`待办列表 - 个人 / 团队`，并提示 `按 H 展开/收起`
- 待办项列表：按优先级色块 + 文本的方式展示
- 已完成分隔区：使用轻分隔线和“已完成”标签
- 底部截断提示：例如“... 还有 12 项”

### 7.3 HUD 视觉规则
- HUD 背景保留半透明深色风格，适应游戏画面
- 文字使用暖白或淡黄，避免纯白刺眼
- 高 / 中 / 低优先级使用红 / 黄 / 绿
- HUD 中的优先级也统一使用色块表达，不只用文字颜色
- 已完成项降低透明度，但仍显示优先级色块
- 折叠状态下只显示标题，展开后显示列表

## 8. 关键交互规则
- 切换空间后，视图区必须同步切换
- 左侧项目按钮固定在底部，不随列表滚动
- 快速新增输入框固定在主内容底部
- 已完成分组使用 `>` / `v` 展示收起状态
- 详情抽屉的关闭按钮独占一行
- 详情标题支持点击进入编辑状态
- 团队空间中的详情按钮纵向排列
- 个人空间中不显示领取、放弃、指派他人
- Project Settings 中角色按钮支持切换，成员支持移出
- Config 中必须带可拖动的 HUD 预览块
- 所有定义为滚动区的列表都要有明确的竖向滚动条表现
